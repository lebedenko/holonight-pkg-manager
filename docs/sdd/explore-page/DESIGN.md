# Explore Page — Design

**Feature**: Read-only search over packages in configured sync databases (libalpm), surfaced on a
new Explore page with an in-memory ranked index, a debounced search field, a read-only details panel shared with the
Installed page, and a local "Reload" button.

**Status**: Design (Stage 2 of SDD cycle)

**Date**: 2026-09-25

**Input**: `docs/sdd/explore-page/SPEC.md` v1.1 (EARS requirements, referenced throughout as `REQ-*`)

**Baseline this design extends**: `docs/sdd/installed-packages-list/DESIGN.md` (port in `domain`, adapter in
`backends`, model in `apps/packages/app/`, `QtConcurrent::run` + `QFutureWatcher`),
`docs/sdd/alpm-sync-db-cache/DESIGN.md` (`AlpmConnectionCache` lease), `docs/sdd/pending-updates/DESIGN.md` (freshness,
stale hint, single-flight reload, page switching, `UpdatesModel`), `docs/sdd/installed-page-ui/DESIGN.md` (details panel,
`HnListDelegate` rows).

---

## 0. Findings that shape the design

Facts about the current code base and about this machine (pacman 7.1.0, libalpm 16.0.1, GCC 16.2.1, i9-14900HX). Sizes
and timings are from the throwaway experiment in §9; nothing touched `/var/lib/pacman` except read-only copies of its
files.

1. **Page switching already exists.** `WorkspaceWindow.qml` hosts a `StackLayout` (`objectName: "workspacePages"`) with
   Installed (index 0) and Updates (index 1), driven by `currentPage` (default `"installed"`) and `Sidebar.qml`'s
   `pageRequested(string)`. `sidebarExploreNav` exists but is `enabled: false`. Because all pages stay instantiated in
   the `StackLayout`, QML-side page state (typed text, selection, scroll) already survives page changes; REQ-F-014
   additionally needs it in the model (§3.4).
2. **The details panel is Installed-specific today.** `PackageDetailPanel.qml` (`required property
   InstalledPackagesFilterModel filterModel`) composes `PackageDetailHeader` (letter tile, name, origin badge, hard-coded
   "Installed" indicator, a Remove button and a more-options button), `PackageDetailMetadataRows` (four hard-coded rows:
   install date, version, size, reason), `PackageDetailDependencySections` (description, "Required by", optional
   dependency chips, "Local state") and `PackageDetailFooterLinks` (four disabled action delegates). It shows **no URL,
   licenses or dependencies**. §4.1 resolves this.
3. **Async pattern** (`InstalledPackagesModel`, `UpdatesModel`): constructor starts `QtConcurrent::run`, a
   `QFutureWatcher<Result>` delivers `finished()` on the GUI thread, results swap in with
   `beginResetModel()/endResetModel()`, one `...Changed()` signal notifies every property, a `loading_` flag makes
   `reload()` single-flight, worker lambdas convert `std::exception`/`...` into a port error.
4. **`AlpmConnectionCache`** returns a move-only lease (`AlpmConnection`) that holds the cache mutex for its lifetime and
   exposes `syncDatabases()` (`std::vector<alpm_db_t*>`, repository name = `sync/*.db` stem, directory-scan order sorted
   lexically). It re-parses only when the `sync/*.db` file list or mtimes change. One instance is owned per source.
   Errors are `PackageSourceError`.
5. **Sync-database inspection is private to `alpm_update_source.cpp`.** `oldestSyncDatabaseTime()` (missing/not-a-dir/no
   `.db` -> "no databases", real I/O errors -> error) and the local-database sanity check (`local/` and
   `ALPM_DB_VERSION` must exist, because `alpm_initialize` would otherwise create them, violating REQ-C-003) live in an
   anonymous namespace / inline in `loadUpdates()`. Explore needs both; §4.2.
6. **Test layout**: one `test_holonight_packages` executable plus `test_runtime_controls`; fixtures under
   `tests/fixtures/pacman/<name>/{local,sync}` (regenerated by a `generate.sh`); `HOLONIGHT_TEST_FIXTURES_DIR` and
   `HOLONIGHT_QML_SOURCE_DIR` compile definitions; internal backend headers reachable via
   `${PROJECT_SOURCE_DIR}/src/backends/src`; models compiled straight from `apps/packages/app/*.cpp` into both test
   executables; a controllable `FakeUpdateSource` in `tests/apps/`; QML tests instantiate components in a
   `QQuickWindow` because layouts and `ListView` delegates are polished only inside one.
7. **Scale on this machine** (measured): 15,287 sync packages (core + extra + g14; multilib is not enabled here, its
   ~200 packages do not change any conclusion).
8. **Mockup** `docs/mockups/explore.png`: title + subtitle, search field, result rows (letter tile, name, repository
   badge, description line, version, download size, Installed state), right-hand details panel with version / installed
   size / license, dependency chips with "+N", installed indicator. AUR, filter chips, sort, Install buttons, package
   health and footer links are out of scope (SPEC non-goals); everything else is in scope.

## 2. Data flow

### 2.1 Load and Reload

Reload is exactly the initial load run again; one worker path, one port call.

```mermaid
sequenceDiagram
    participant QML as ExploreView.qml / Reload button
    participant Model as ExploreModel (GUI thread)
    participant Pool as QtConcurrent pool
    participant Src as AlpmExploreSource
    participant Cache as AlpmConnectionCache (own instance)
    participant Alpm as libalpm

    Note over Model: constructor: state = Loading, loading_ = true
    QML->>Model: reload()  (later, user action)
    alt loading_
        Model-->>QML: ignored (single-flight)
    else idle
        Model->>Model: loading_ = true (state = Loading only if there is no index), emit stateChanged
    end
    Model->>Pool: QtConcurrent::run(load)
    Pool->>Src: loadPackages()
    Src->>Src: oldestSyncDatabaseTime(dbpath) (missing/not-dir/none => databasesFound=false, returns here)
    Src->>Src: checkLocalDatabase(dbpath) (missing => DatabaseOpenFailed)
    Src->>Cache: connection() (lease; re-parses only if file list/mtimes changed)
    Src->>Alpm: alpm_initialize(root, dbpath) -> fresh local handle; name->version map of local db
    Src->>Src: for each sync db, for each pkg: convert to SyncPackage (+ installedVersion)
    Src-->>Pool: expected<ExploreSnapshot, ExploreSourceError>
    Pool->>Pool: ExploreIndex(std::move(packages)) (folded name/description copies)
    Pool-->>Model: QFutureWatcher::finished (GUI thread)
    Model->>Model: success: swap index_, dataAsOf, stale; re-run current query at once (no debounce); state = NoDatabases | Hint | NoMatches | Results
    Model-->>QML: stateChanged()
```

The path never writes under the dbpath and makes no network call (REQ-C-003, REQ-C-004). `ExploreIndex` is immutable and
held as `std::shared_ptr<const ExploreIndex>`: built on the worker, then only read on the GUI thread.

### 2.2 Search (GUI thread, no worker)

```mermaid
sequenceDiagram
    participant Field as HnSearchField
    participant Model as ExploreModel
    participant Fn as searchPackages() (pure)

    Field->>Model: searchText = "vi" ... "vim"  (each keystroke; searchText updates immediately)
    Model->>Model: restart single-shot QTimer (debounce interval)
    Note over Model: timer fires once, after the last keystroke
    Model->>Model: trim(query) empty -> state = Hint, rows cleared, NO search executed
    Model->>Fn: searchPackages(*index_, trimmedQuery, 500)
    Fn-->>Model: {rows (<= 500 indexes), totalMatches}
    Model->>Model: beginResetModel; results_ = rows; endResetModel; reconcile selection; state = Results | NoMatches
    Model-->>Field: stateChanged / rowsReset
```

Search runs synchronously on the GUI thread (§4.4 decision). While a load is in flight with no index the field is
disabled; a query set programmatically in that window is kept and executed when the index arrives.

### 2.3 Failure

Any failure (database open/registration/parse failure, missing local database, unexpected exception) yields
`std::unexpected(ExploreSourceError)`. In the model:

* **Reload failure with an index** (state `Hint`, `NoMatches`, `Results` or `NoDatabases`): index, rows, `dataAsOf`,
  selection and `state` stay exactly as they were; `loading_` becomes false; `reloadErrorMessage` is set; QML shows the
  banner "Reload failed: {reason}. Showing data from {dataAsOfLabel}." (the "Showing data" sentence is omitted when there
  is no `dataAsOf`, as on the Updates page). Search keeps working against the old index.
* **Initial-load failure** (or reload from `Error`): no index; rows cleared, `state = Error`, `errorMessage` set, Reload
  enabled. A Reload pressed in `Error` is a fresh initial load (state returns to `Loading`).

No automatic retry. A later successful load clears both messages.

## 3. Interfaces

### 3.1 Domain types (`sync_package.h`)

```cpp
namespace holonight_packages_domain {

// One package as it appears in one sync database. Distinct from the installed `Package`: no install date, reason,
// required-by or config-file data, and it carries sync-only metadata (URL, licenses, dependencies, download size).
struct SyncPackage {
  std::string name;
  std::string version;                              // version offered by the repository
  std::string repository;                           // sync database name (file stem), e.g. "core"
  std::string description;                          // empty when the database has none
  std::string url;                                  // upstream URL as stored; empty when absent
  std::vector<std::string> licenses;
  std::vector<std::string> dependencies;            // alpm_dep_compute_string form, e.g. "glibc>=2.38"
  std::vector<std::string> optionalDependencies;    // "name: reason" form
  std::uint64_t downloadSizeBytes = 0;              // alpm_pkg_get_size: compressed package size
  std::uint64_t installedSizeBytes = 0;             // alpm_pkg_get_isize
  // Version of the same-named package in the local database; nullopt when not installed. Filled by the adapter from the
  // local database read in the same load, so it is as fresh as the load.
  std::optional<std::string> installedVersion;

  bool operator==(const SyncPackage&) const = default;
};

struct ExploreSnapshot {
  std::vector<SyncPackage> packages;                // every (repository, name) entry; order unspecified
  bool databasesFound = true;                       // false => "No package databases found" (not an error)
  std::chrono::system_clock::time_point dataAsOf;   // mtime of the OLDEST sync *.db; meaningless when !databasesFound

  bool operator==(const ExploreSnapshot&) const = default;
};

}  // namespace holonight_packages_domain
```

Identity of a row is `repository + "/" + name`. Packages present in more than one sync database (for example a
third-party repository shadowing an official one) are **all** listed, as `pacman -Ss` does, unlike the Updates page which
follows pacman's "first repository wins" installation rule.

### 3.2 Port (`explore_source.h`)

```cpp
enum class ExploreSourceErrorCode : std::uint8_t { DatabaseOpenFailed, Unknown };

struct ExploreSourceError {
  ExploreSourceErrorCode code;
  std::string message;   // user-presentable reason (banner / error state text)
};

class ExploreSource {
 public:
  /* rule-of-five defaulted like UpdateSource */
  virtual ~ExploreSource();

  // Read-only enumeration of every package in the current live sync databases. No network, never writes. Blocking;
  // called on a worker thread. Serves both the initial load and Reload.
  [[nodiscard]] virtual std::expected<ExploreSnapshot, ExploreSourceError> loadPackages() const = 0;
};
```

No `ConfigurationInvalid` code: Explore does not read `pacman.conf`. "Index building" in REQ-F-013 is the application
layer's `ExploreIndex` (§3.3), constructed on the worker thread right after `loadPackages()`; the port only enumerates.

### 3.3 Search and ranking (`explore_search.h`, application layer; Qt-free public API)

```cpp
namespace holonight_packages_application {

inline constexpr std::size_t kMaxSearchResults = 500;

// Immutable search index over one snapshot. Built once per load; never mutated (safe to share read-only).
struct SearchResult;

class ExploreIndex {
 public:
  explicit ExploreIndex(std::vector<holonight_packages_domain::SyncPackage> packages);
  [[nodiscard]] const std::vector<holonight_packages_domain::SyncPackage>& packages() const;
  [[nodiscard]] std::size_t size() const;
 private:
  friend SearchResult searchPackages(const ExploreIndex&, std::string_view, std::size_t);
  std::vector<holonight_packages_domain::SyncPackage> packages_;
  std::vector<std::string> folded_names_;          // Unicode case-folded UTF-8 copies, built once
  std::vector<std::string> folded_descriptions_;
};

struct SearchResult {
  std::vector<std::uint32_t> rows;   // indexes into index.packages(), ranked, at most `limit`
  std::size_t totalMatches = 0;      // matches before the cap (REQ-F-005 footer count)
};

// Case-insensitive, literal (no regex/glob, no tokenising: "kernel mod" is one substring). The query is trimmed of
// ASCII whitespace first; an empty result (totalMatches == 0) is returned for an empty/whitespace-only query so callers
// cannot accidentally list everything.
[[nodiscard]] SearchResult searchPackages(const ExploreIndex& index, std::string_view query,
                                          std::size_t limit = kMaxSearchResults);

}  // namespace holonight_packages_application
```

Semantics (REQ-F-003):

* Rank per package: `0` name equals query; `1` name starts with query (and is not equal); `2` name contains query;
  `3` name does not contain it but the description does. Anything else does not match.
* Order: `(rank, folded name, original index)`. Within a rank the order is alphabetical by name, with the original index
  as a total-order tie-break (same name in two repositories keeps sync-database order). The comparator is a strict weak
  ordering over distinct indexes, so the result is deterministic.
* Cap: `std::partial_sort` of the first `min(limit, matches)` hits; `totalMatches` counts all matches.
* Case folding uses `icu::UnicodeString::foldCase()` during index construction and on each query. The public search API and
  domain types use standard C++ values; only the application implementation links ICU. Non-ASCII description text
  therefore matches without regard to case.

### 3.4 `ExploreModel` (`apps/packages/app/ExploreModel.h`)

```cpp
class ExploreModel : public QAbstractListModel {
  Q_OBJECT
  QML_NAMED_ELEMENT(ExploreModel)
  QML_UNCREATABLE("ExploreModel is provided by the application")
  Q_PROPERTY(ViewState state READ state NOTIFY stateChanged)
  Q_PROPERTY(bool loading READ loading NOTIFY stateChanged)                // initial load OR reload in flight
  Q_PROPERTY(bool searchEnabled READ searchEnabled NOTIFY stateChanged)    // an index exists (see below)
  Q_PROPERTY(QString errorMessage READ errorMessage NOTIFY stateChanged)   // state Error only
  Q_PROPERTY(QString reloadErrorMessage READ reloadErrorMessage NOTIFY stateChanged)  // empty = no failure
  Q_PROPERTY(QString searchText READ searchText WRITE setSearchText NOTIFY searchTextChanged)  // raw field text
  Q_PROPERTY(int matchCount READ matchCount NOTIFY stateChanged)           // total matches, before the cap
  Q_PROPERTY(QString footerText READ footerText NOTIFY stateChanged)       // empty unless matchCount > rowCount
  Q_PROPERTY(QString noMatchesText READ noMatchesText NOTIFY stateChanged) // "No packages match '%1'. Note: ..."
  Q_PROPERTY(QDateTime dataAsOf READ dataAsOf NOTIFY stateChanged)         // invalid when none
  Q_PROPERTY(QString dataAsOfLabel READ dataAsOfLabel NOTIFY stateChanged) // "Data as of Sep 22, 14:30"
  Q_PROPERTY(bool databasesStale READ databasesStale NOTIFY stateChanged)
  Q_PROPERTY(QString staleHintText READ staleHintText CONSTANT)
  Q_PROPERTY(QString repositoryScopeNote READ repositoryScopeNote CONSTANT)
  Q_PROPERTY(int currentRow READ currentRow WRITE setCurrentRow NOTIFY currentRowChanged)
  Q_PROPERTY(QVariantMap currentPackage READ currentPackage NOTIFY currentPackageChanged)

 public:
  // Loading only while there is no index to show; a reload with an index keeps its state and sets `loading`.
  enum class ViewState : std::uint8_t { Loading, NoDatabases, Error, Hint, NoMatches, Results };
  Q_ENUM(ViewState)

  enum Role : std::uint16_t {
    NameRole = Qt::UserRole + 1, AvailableVersionRole, RepositoryRole, DescriptionRole,
    DownloadSizeRole /*quint64*/, DownloadSizeLabelRole, InstalledSizeRole /*quint64*/, InstalledSizeLabelRole,
    UrlRole, LicensesRole /*QStringList*/, DependenciesRole /*QStringList*/, OptionalDependenciesRole /*QStringList*/,
    IsInstalledRole, InstalledVersionRole, InstalledBadgeTextRole, InstalledVersionDiffersRole
  };

  using Clock = std::function<std::chrono::system_clock::time_point()>;
  static constexpr std::chrono::milliseconds kDefaultSearchDebounce{150};

  // `now` and `debounce` are injectable for deterministic staleness and debounce tests.
  explicit ExploreModel(std::shared_ptr<holonight_packages_domain::ExploreSource> source, QObject* parent = nullptr,
                        Clock now = &std::chrono::system_clock::now,
                        std::chrono::milliseconds debounce = kDefaultSearchDebounce);
  ~ExploreModel() override;
  /* non-copyable, non-movable */

  /* rowCount / data / roleNames as in UpdatesModel */
  Q_INVOKABLE void reload();                   // single-flight; no-op while loading
  void setSearchText(const QString& text);     // no-op if unchanged; (re)starts the debounce timer
  void setCurrentRow(int row);                 // out of range -> -1
  [[nodiscard]] int searchCount() const;       // number of searches actually executed (diagnostics and debounce tests)
};
```

Role names (QML): `name`, `availableVersion`, `repository`, `description`, `downloadSize`, `downloadSizeLabel`,
`installedSize`, `installedSizeLabel`, `url`, `licenses`, `dependencies`, `optionalDependencies`, `isInstalled`,
`installedVersion`, `installedBadgeText`, `installedVersionDiffers`. `currentPackage` is a `QVariantMap` of all roles for
the selected row (same construction as `InstalledPackagesFilterModel::get()`).

Members: `std::shared_ptr<ExploreSource> source_`, `Clock now_`, `QFutureWatcher<LoadResult> watcher_`,
`std::shared_ptr<const ExploreIndex> index_`, `std::vector<std::uint32_t> results_`, `QTimer search_timer_` (single
shot, interval = `debounce`), `QString search_text_`, `QString applied_query_` (trimmed query the rows correspond to),
`std::size_t match_count_`, `bool loading_`, `ViewState state_`, `QString error_message_`, `QString
reload_error_message_`, `QDateTime data_as_of_`, `bool databases_stale_`, `int search_count_`, `int current_row_`,
`QString selected_identity_`, `QVariantMap current_package_`. `LoadResult = std::expected<LoadedIndex,
ExploreSourceError>` where the worker-side `LoadedIndex { std::shared_ptr<const ExploreIndex> index; bool
databasesFound; time_point dataAsOf; }` is copyable, as `QFutureWatcher` requires.

Semantics:

* **Load** (`startLoading()`): `loading_ = true`; `state_ = Loading` only when there is no index; the worker lambda calls
  `source->loadPackages()`, builds `ExploreIndex` from the moved-out packages, catches `std::exception` and `...` and
  converts them to `ExploreSourceError{Unknown, ...}` exactly like `UpdatesModel::startLoading()`.
  `reload()` returns immediately if `loading_` (double press and press during the initial load, REQ-F-008/NF-002).
* **On success**: compute replacement results against the new index, then swap `index_` and result rows inside one
  `beginResetModel()`/`endResetModel()` pair on the GUI thread. Set `data_as_of_ = toQDateTime(...)`, `databases_stale_ = databasesFound &&
  isStale(dataAsOf, now_())` (strictly greater than 7 days), clear both error messages; `!databasesFound` ->
  `state_ = NoDatabases`, index dropped, rows cleared, no `dataAsOf`; otherwise **run the current query immediately**
  (`runQuery()`, no debounce, cancelling a pending timer) which sets `Hint`, `NoMatches` or `Results`. The query text is
  preserved across reloads (REQ-F-008).
* **`runQuery()`**: trim `search_text_`; if empty -> `Hint`, `results_` cleared, `match_count_ = 0`, **no search
  executed**; else `++search_count_`, `searchPackages(*index_, trimmed, kMaxSearchResults)`, reset the model with the
  ranked rows, `Results` if `totalMatches > 0` else `NoMatches`. Then reconcile the selection.
* **`setSearchText`**: stores the raw text and emits `searchTextChanged` immediately, then restarts the timer. The timer
  slot calls `runQuery()` only if an index exists; otherwise it does nothing (a later load applies the query). Emptying the
  field goes through the same debounce, so "n keystrokes within the window -> one execution" also holds for deletions.
* **`searchEnabled`** = an index exists (`state` is `Hint`, `NoMatches` or `Results`). It stays true during a reload, so
  the user can keep searching the old index; it is false while `Loading`, `NoDatabases` and `Error` (REQ-F-002/007: the
  field is disabled during index construction). Flipping "disabled during reload too" costs one expression.
* **Cap and footer** (REQ-F-005): `rowCount() <= 500`; `matchCount` is the real total; `footerText` is
  `tr("Showing first %1 of %2 matches, refine your search to find what you're looking for.")` only when
  `matchCount > rowCount()`, else empty (exactly 500 matches -> no footer).
* **No matches** (REQ-F-010): `noMatchesText` names the query and explains that configured sync repositories are
  searched, while AUR and local-only packages are excluded.
* **Installed badge** (REQ-F-004): `installedBadgeText` is empty when not installed, `tr("Installed")` when
  `installedVersion == version`, `tr("Installed %1").arg(installedVersion)` otherwise; `installedVersionDiffers` lets QML
  render the second case subdued.
* **Selection** (REQ-F-006/014): `setCurrentRow(row)` stores `current_row_`, `selected_identity_ = repository + "/" +
  name` and rebuilds `current_package_`. After every result swap the model looks for `selected_identity_` in the new
  rows: found -> keep it (row index updated, `currentRow` notifies), not found -> `current_row_ = -1`,
  `current_package_` cleared. While a reload keeps the old rows the selection is untouched. Selection and query live in
  the model, so they survive navigation regardless of QML item lifetime and are never persisted (REQ-NF-003).
* **Failure**: as in §2.3; the `applyFailure` split between "index exists" and "no index" mirrors `UpdatesModel`.
* No index, query, selection or freshness state is written to disk or `QSettings`; a fresh model always starts in
  `Loading` with an empty query and zero rows (REQ-F-007, NF-003).
* `dataAsOfLabel`, `toQDateTime`, `staleHintText` come from `DataFreshness` (§4.2). `repositoryScopeNote` explains the
  configured sync-repository scope; Updates retains its own different scope note.

`ExploreModel` states, exclusive: `Loading` (no index, load in flight), `NoDatabases` (no `.db` files), `Error`,
`Hint` (index, empty/whitespace query), `NoMatches`, `Results`. QML compares against them with `===` only; it must never
bind `ExploreModel.Results` etc. declaratively to a `ViewState`-typed property (qmlcachegen crash,
`docs/known-issues/qmlcachegen-enum-binding-crash.md`).

### 3.5 Adapter (`alpm_explore_source.h`) and wiring

```cpp
namespace holonight_packages_backends {

// Every path the adapter touches comes from here; it holds no default pacman locations (REQ-C-001).
struct AlpmExploreSourceOptions {
  std::filesystem::path databaseRoot;   // libalpm root directory
  std::filesystem::path databasePath;   // libalpm database path, containing local/ and sync/
};

class AlpmExploreSource : public holonight_packages_domain::ExploreSource {
 public:
  explicit AlpmExploreSource(AlpmExploreSourceOptions options);
  ~AlpmExploreSource() override;
  /* non-copyable, non-movable like AlpmUpdateSource */

  [[nodiscard]] std::expected<holonight_packages_domain::ExploreSnapshot, holonight_packages_domain::ExploreSourceError>
  loadPackages() const override;

 private:
  AlpmExploreSourceOptions options_;
  std::unique_ptr<holonight_packages_persistence::AlpmConnectionCache> connection_cache_;
};

}  // namespace holonight_packages_backends
```

`loadPackages()` steps: (1) `oldestSyncDatabaseTime` -> none: `ExploreSnapshot{.databasesFound = false}`; (2)
`checkLocalDatabase`; (3) `connection_cache_->connection()`; (4) fresh local handle via `alpm_initialize`, build
`std::unordered_map<std::string, std::string>` name -> version from the local package cache (same error handling as
`AlpmUpdateSource`); (5) for each `alpm_db_t*` in `connection->syncDatabases()` (registration order) iterate
`alpm_db_get_pkgcache`, convert with null-safe accessors (`alpm_pkg_get_name/version/desc/url/licenses/depends/
optdepends/size/isize`, `alpm_dep_compute_string` freed with `free`, as `populateExtendedFields` does), repository =
`alpm_db_get_name`; (6) `dataAsOf = clock_cast<system_clock>(oldest)`. A null name or version aborts the load with
`DatabaseOpenFailed` (same stance as `convertPackageFields`); other null fields become empty. The lease is held for the
whole conversion (about 10 ms), which is the cache's designed contract.

`PackagesApplication.cpp`:

```cpp
auto explore_source = std::make_shared<holonight_packages_backends::AlpmExploreSource>(
```

`PackagesApplication.h` gains a forward declaration and `std::unique_ptr<ExploreModel> explore_model_`. The destructor
resets `view_`, then `explore_model_`, `updates_model_`, `installed_packages_model_`. The production path literals stay
in `PackagesApplication.cpp` only; the adapter has none (REQ-C-001).

## 4. Resolution of the open items

### 4.1 Details panel sharing

**Decision.** Installed and Explore use the same `PackageDetailFrame` for the empty state and scrolling shell, and the
same `PackageDetailContent` for the header, metadata rows, description, spacing and margins. The content component
accepts page-specific metadata rows and optional extra and footer components. Installed supplies required-by, optional
dependencies, local state and footer links; Explore supplies dependencies and optional dependencies without installed-only
sections or actions. The two panels keep their model-specific `currentPackage` mapping and fully keyed empty fallbacks.

`PackageDetailHeader` and `PackageDetailMetadataRows` remain shared inside that layout. Explore passes a repository badge
without claiming a third-party repository is official. `PackageDetailDependencySections` retains its public properties
for existing callers; Installed suppresses its description because `PackageDetailContent` renders the shared description.
The Installed panel's public `filterModel` API and shared object names remain unchanged.

The panels cannot show identical field lists: the installed domain package has install date, reason and required-by data,
while the sync package has URL, licenses, dependencies and download size. REQ-F-006 therefore requires a shared layout
for common fields and page-specific field sets, which the implementation provides.

### 4.2 Open Design Question 2: freshness and reload factoring

**What the code shows.** Comparing `UpdatesModel` with what `ExploreModel` needs, the genuinely shared pieces are small:

| Piece | Where in `UpdatesModel` | Size | Same in Explore? |
|---|---|---|---|
| 7-day rule (`kStaleAfter`, `now_() - dataAsOf > kStaleAfter`) | header + 1 line in `applySnapshot` | ~3 lines | identical |
| `toQDateTime(time_point)` | anon. namespace | 4 lines | identical |
| `dataAsOfLabel()` ("Data as of %1", `QLocale::ShortFormat`) | member | ~5 lines | identical |
| Stale-hint wording | hard-coded in `UpdatesView.qml` | 1 string | must be identical (SPEC) |
| Single-flight `reload()` + `startLoading()` try/catch lambda + `onLoadFinished()` | member functions | ~25 lines | same shape, different result/state types (`UpdateSnapshot` vs `LoadedIndex`) |
| Failure split (keep previous data + banner vs `Error`) | `applyFailure` | ~15 lines | same idea, different state enum and different data to keep |
| QML: Reload button, banner text (`reloadBannerText`), progress bar, `UpdatesInlineNotice` | `UpdatesView.qml` | ~35 lines | banner text and button repeated; notice is a reusable component |

So the honest total is about 11 lines of pure, stateless logic plus one string, and roughly 40 lines of stateful plumbing
per model that differ in their types and state machines.

**Decision.** Extract only the stateless, byte-identical pieces; do not create a base class or mixin.

* `src/application/include/holonight_packages_application/data_freshness.h` (header-only, Qt-free):
  `inline constexpr std::chrono::days kStaleAfter{7};` and `[[nodiscard]] constexpr bool isStale(time_point dataAsOf,
  time_point now) { return now - dataAsOf > kStaleAfter; }`. Layering: pure `std::chrono`, so it belongs in the
  application layer where `summarizeUpdates` lives, and it gets its own boundary test (6 d / 7 d / 8 d / 2 h).
* `apps/packages/app/DataFreshness.h/.cpp` (Qt-side, free functions in a namespace): `toQDateTime`, `dataAsOfLabel`
  (using `QCoreApplication::translate("DataFreshness", ...)`, since a free function has no `tr`), `staleHintText()`.
  `UpdatesModel` is changed to call them and to expose `staleHintText` (`Q_PROPERTY(... CONSTANT)`, exactly like
  `officialOnlyNote`); `UpdatesView.qml` binds its stale hint to it. Both pages therefore show the same wording from one
  source (REQ-F-011 "match the Updates page" becomes structural, and a test asserts both models return the same string).
  There are no `.ts` translation files in the repository, so moving the translation context costs nothing.
* **Duplicated on purpose**: the load/reload plumbing (~25 lines) and the failure split, in `ExploreModel`; and in QML the
  Reload button and the reload-banner text. Reuse for QML: `ExploreView` imports `"../updates"` and uses
  `UpdatesInlineNotice` unchanged for the banner and the stale hint (precedent: `PackageOriginBadge` is imported across
  features the same way; `WorkspaceWindow` already imports both feature directories).

**Rationale.** A base class cannot remove the plumbing: `Q_OBJECT` classes cannot be templates, so a shared
`QFutureWatcher<T>` owner would need type erasure (`QFutureWatcher<std::any>`-style) to hide two different result types,
which is more code and less clarity than the ~25 lines it would replace; the state enums, the "previous data" concept
(a list vs an index plus query/selection) and the summary properties differ, so a base would need hooks for almost
everything. A shared helper for the stateless pieces removes the only risks that matter (7-day rule and wording drifting
apart) for ~15 lines of new code and a small mechanical edit to `UpdatesModel`, guarded by the existing
`updates_model_test`/`updates_view_test`.

**Alternatives.** (a) Full duplication: rejected only because the wording and the 7-day rule are required to match; the
cost of one shared header is tiny. (b) Abstract `FreshnessModelBase : QAbstractListModel` with `loading`, `reload`,
`dataAsOf`, `stale`, banner: rejected as above (would also force `Q_PROPERTY` NOTIFY signals into a base and make
`UpdatesModel` tests depend on it). (c) A QML singleton for the strings: rejected, over-scoped for one sentence. (d) Move
`UpdatesInlineNotice` to a shared `qml/common/` directory and rename: sensible cleanup, not required; listed in §10.

### 4.3 Placement and cache coexistence

* **Port and types**: `src/domain`, so models and tests build without libalpm (same rule as `PackageSource`,
  `UpdateSource`).
* **Adapter**: a new `AlpmExploreSource` with its **own** `AlpmConnectionCache(databaseRoot, databasePath)`, matching
  "owned per source instance" (alpm-sync-db-cache). It uses `connection()` for sync databases and a fresh scoped handle for
  the local database, mirroring `AlpmUpdateSource`. A Reload after the user synced manually is picked up because the cache
  re-parses when the file list or mtimes change; an unchanged Reload skips the ~100 ms parse and only re-reads the local
  database and re-converts (≈15 ms measured, §9).
* **Memory cost of a third cache**: each source keeps libalpm's parsed copy alive (measured 42.1 MiB heap per copy). The
  application now holds three (Installed, Updates, Explore), ≈126 MiB, plus Explore's own index (≈13.8 MiB). Accepted for
  v1 because sharing one cache changes `AlpmPackageSource`/`AlpmUpdateSource` ownership (as deferred in pending-updates
  DESIGN §5); listed as an open item with two concrete options in §10.
* **Model**: `apps/packages/app/ExploreModel`, as for the other models.

### 4.4 Open Design Question 3: index size and search thread model

**Historical ASCII-folding baseline**, measured before the Unicode correction on copies of core, extra, g14 (§9).
The package counts and libalpm parse cost remain useful; index-build and search timings have not been remeasured with
Unicode folding:

| Quantity | Value |
|---|---|
| Packages indexed | 15,287 |
| libalpm parse of the three databases (kept alive by the cache) | 95-107 ms, +42.1 MiB heap |
| `SyncPackage` copy of all fields (`sizeof` 248 B + strings/vectors) | 10-12 ms (-O2), 27 ms (-O0); +11.2 MiB heap |
| Folded name/description copies (variant A) | 1.3-1.7 ms (-O2), 4.5 ms (-O0); +2.1 MiB heap |
| Index memory we own (SyncPackage vector + folded copies) | ≈13.3 MiB measured, ≈13.8 MiB with `optional<string> installedVersion` |
| Raw text content of all stored fields (names 0.20, descriptions 0.70, everything 2.86 MiB) | 2.86 MiB |
| Local database read (1,847 installed) | 1.3-2.9 ms |
| Worker total on a cold cache | ≈110-125 ms; on an unchanged Reload ≈15 ms |

Search (precomputed folded copies = variant A; on-the-fly folding = variant B), median of 30 runs, single thread, top-500
via `partial_sort`, 15,287 packages:

| Query (chars) | Matches (shown) | A, -O2 | B, -O2 | A, -O0 (Debug) | B, -O0 |
|---|---|---|---|---|---|
| `a` (1) | 14,642 (500) | 0.29 ms | 0.47 ms | 1.42 ms | 2.33 ms |
| `e` (1) | 14,974 (500) | 0.30-0.36 ms | 0.48-0.52 ms | 1.53 ms | 2.33 ms |
| `s` (1) | 13,763 (500) | 0.36 ms | 0.51-0.56 ms | 1.58 ms | 2.72 ms |
| `linux` (5) | 334 | 0.48 ms | 0.96 ms | 1.39 ms | 5.07 ms |
| `brows` (5) | 88 | 0.31 ms | 0.71 ms | 1.12 ms | 4.54 ms |
| `python` (6) | 2,203 (500) | 0.40 ms | 0.72-0.77 ms | 1.36 ms | 4.33 ms |
| `python-req` (10) | 17 | 0.38 ms | 0.86 ms | 1.17 ms | 4.80 ms |
| `kernel mod` (10) | 18 | 0.23 ms | 0.66-0.69 ms | 0.98 ms | 4.45 ms |
| `zzzzzzzz` (8, no match) | 0 | 0.19 ms | 0.61-0.63 ms | 0.90 ms | 4.31 ms |

The 1-character queries are the worst case for the sort (about 96% of packages match). The historical worst measured
search was 0.5 ms optimised and 1.6 ms in a Debug build. Recheck those figures for the Unicode-folded index before
using them as a current performance claim.

**Decision: run the search synchronously on the GUI thread; keep the load off-thread.**

* The previous ASCII-folding implementation used 3-10% of a frame in the measured configuration. The folded strings
  are still precomputed, but current search and index-build costs need measurement after the Unicode change.
* Off-thread search would add cancellation/generation tokens, stale-result discarding and a second model state for no
  user-visible gain; a synchronous search also cannot race the index swap or the selection reconcile (all on the GUI
  thread).
* Keep folded name/description copies so searches do not fold every package on each query. The previous ASCII
  implementation measured +2.1 MiB and 1.7 ms to build these copies; the Unicode version needs a new measurement.
* The index build (conversion + folding) and the libalpm parse stay on the worker thread (REQ-F-007,
  REQ-NF-002); only the swap happens on the GUI thread.
* **Revisit trigger** (recorded, not built): if a search on a target machine measures above ~8 ms (half a frame) in the
  shipped build, move `searchPackages` to `QtConcurrent::run` with a generation counter. The function is pure and the
  index immutable, so that is a local change in `ExploreModel::runQuery`. The historical measurement ran on an i9-14900HX;
  slower CPUs scale it, which is why the trigger is an absolute number and not a ratio.

**Debounce: 150 ms** (`ExploreModel::kDefaultSearchDebounce`, injectable). The debounce coalesces keystroke bursts so
the model is not reset and the `ListView` not rebuilt
on every key. 150 ms is short enough to feel immediate after the last key and long enough to absorb typical inter-key gaps
(≈80-200 ms) for the common fast-typing burst. The spec's "e.g. 300 ms" is an example, not a requirement; 300 ms would add
latency the measurements show is unnecessary. Tests inject 25 ms (§7.2).

Not measured (by design; visual/GUI verification is manual): delegate creation and layout cost of a 500-row reset. The
`ListView` instantiates only visible delegates, so this is bounded by the viewport, not by the 500 cap.

## 5. Key decisions and rationale

| Decision | Rationale |
|---|---|
| Distinct `SyncPackage`, not the installed `Package` | Different fields (URL, licenses, dependencies, download size vs install date, reason, required-by); avoids empty/meaningless fields and a lossy adapter (REQ-F-006 constraint) |
| `installedVersion` carried on `SyncPackage`, filled in the same load | One consistent snapshot; no second port call; badge and Reload stay coherent; the installed state can only go stale until the next Reload, which is stated in the UI by the freshness label |
| All `(repository, name)` entries listed | Discovery matches `pacman -Ss`; identity includes the repository |
| Index built in the application layer on the worker, port only enumerates | Testable without ALPM or QML; the port stays a thin read |
| Search on the GUI thread, precomputed folded copies | §4.4 measurements |
| Debounce 150 ms, injectable; trailing edge; empty query does no search | §4.4; hint state without executing a search |
| Unicode case folding | ICU handles full Unicode case folding in descriptions; the search API still uses standard C++ types |
| Immutable `shared_ptr<const ExploreIndex>` | Built on the worker, read on the GUI thread, no locking |
| Query and selection live in the model | REQ-F-014 independent of QML lifetimes; mirrors filter model's `currentRow` |
| Reload keeps query, index (until replaced), selection (if still present) | REQ-F-008, no flicker |
| Search field enabled during reload when an index exists | REQ-F-002 speaks of the initial construction; the old index is valid to search; one-expression change if the reviewer wants it disabled |
| Explore does not read `pacman.conf` | Ignore lists do not affect search; fewer failure modes (`ConfigurationInvalid` not needed) |
| Shared details components via plain-property contract | §4.1 |
| Extract only stateless freshness pieces | §4.2 |
| Own `AlpmConnectionCache` | Consistent with the existing per-source rule; memory cost recorded (§4.3, §10) |
| Explore is appended as the third `StackLayout` page; Installed stays landing | REQ-C-006; existing index assertions stay valid |
| Scheme-less URLs in fixtures | REQ-C-004 inspection forbids `http://` / `https://` anywhere in new source and test code; the panel shows the string as stored |

## 6. Alternatives considered

| Alternative | Verdict |
|---|---|
| Search off-thread with cancellation | Rejected by measurement (§4.4); revisit trigger recorded |
| Fold case in the QML-facing model | Rejected: folding once while building `ExploreIndex` avoids repeated work per query |
| Index only names, fetch descriptions lazily from libalpm | Rejected: needs the cache lease held at search time, couples search to libalpm, and description search is a requirement |
| Full sort of all matches instead of `partial_sort` | Rejected: O(m log m) for m up to ~15,000 vs O(m log 500); the cap makes partial sort sufficient (and `totalMatches` is computed independently) |
| Store `std::string_view` into libalpm memory instead of copying | Rejected: ties index lifetime to the cache/handle and to the lease mutex; the copy costs 12 ms and 11 MiB and lets the handle be released later |
| Lazy first-visit load of the Explore model | Rejected for v1: `ExploreModel` starts in `Loading` from construction (REQ-F-007, NF-003 tests) and matches the other models; cost noted in §10 |
| Shared single `AlpmConnectionCache` across the three sources | Deferred (§4.3, §10) |
| Introduce a `FreshnessModelBase` / mixin | Rejected (§4.2) |
| Explore as default landing page | Rejected by REQ-C-006 |
| Live-filtering the list as the user types with no debounce | Rejected by REQ-F-002 |
| `IPackageDetailsProvider` / polymorphic package model | Rejected (§4.1) |

## 8. Known risks and build consequences

* **Build**: `apps/packages/CMakeLists.txt` adds `ExploreModel` and `DataFreshness` to the executable sources and
  `ExploreModel.h` to the QML module `SOURCES`; `src/*/CMakeLists.txt` add the new `.cpp` files; `tests/CMakeLists.txt`
  adds the new test files and compiles `ExploreModel.cpp`/`DataFreshness.cpp` into `test_holonight_packages` and
  `test_runtime_controls` (`UpdatesModel.cpp` now needs `DataFreshness.cpp` in both). ICU is added for full Unicode case
  folding; `README.md` records the new build requirement. `scripts/check-qmltypes.sh` must list `ExploreModel`, otherwise CI's "QML type
  metadata" step would not notice a missing registration.
* **`qmlcachegen` / `qmllint`**: new QML must be checked against the two known issues in `docs/known-issues/`.
* **`WorkspaceWindow` gains a required property**: anything instantiating it without `exploreModel` fails at load (the
  three existing creation sites are updated in this change, §7.2).
* **Header/library skew**: only symbols exercised in the §9 experiment (`alpm_pkg_get_url/licenses/depends/optdepends/
  size/isize/desc`, `alpm_dep_compute_string`) are used; behaviour under other libalpm versions is unverified.
* **Snapshots are two-phase for installed state**: the local database is read at load time; installs done outside the app
  are reflected only after Reload (the freshness label reflects the sync databases, not the local one).
* **Refactors of shared code** (`alpm_update_source.cpp` helpers, `UpdatesModel`, five Installed QML files) are
  behaviour-preserving and guarded only by existing tests; run the full suite (both Quick Controls styles in CI) after
  each step.

## 9. Experiments (throwaway, scratchpad only; nothing in the repo or `/var/lib/pacman` was modified)

The throwaway measurement sources (`measure.cpp`, `local.cpp`) were kept outside the repository and are not retained.
Environment: pacman 7.1.0 / libalpm 16.0.1, GCC 16.2.1, Intel i9-14900HX, 32 threads, 64 GB.

Method: the three files of `/var/lib/pacman/sync/` (`core.db`, `extra.db`, `g14.db`; 9.0 MB together) were copied into the
scratchpad; a scratch dbpath with an empty local database (`ALPM_DB_VERSION` = 9) and an empty root was used; databases
were registered with `alpm_register_syncdb` and their package caches loaded. The program then copied every package into
the `SyncPackage` layout of §3.1 (name, version, repository, description, URL, licenses, dependencies via
`alpm_dep_compute_string`, optional dependencies, sizes), built the folded name/description copies, and ran the ranked
search (variant A: precomputed folded strings and `std::string::find`; variant B: fold on the fly with `std::search`) 30
times per query, reporting the median. Heap figures are `mallinfo2` in-use bytes deltas (not RSS; RSS +46 MiB for the first
libalpm load). Three runs; the first includes cold effects, results agree within ~10%. Compiled with `-O2` and `-O0` (the
project builds Debug by default). `local.cpp` read a copy of the real local database (1,847 packages).

Results are the tables in §4.4. Additional observations:

1. libalpm loads the **full** description of every sync package when the cache is populated (42.1 MiB heap for 15,287
   packages), so URL/licenses/dependencies cost nothing extra to read at conversion time.
2. The queries `a`/`e`/`s` match 90-98% of all packages (name or description), which is the sort-heavy worst case.
3. A one-shot conversion (10-12 ms) plus folding (1.7 ms) is negligible next to the parse (≈100 ms); an unchanged Reload
   skips only the parse.

**Assumed (not verified)**: behaviour on other libalpm versions; performance on slower CPUs (see the revisit trigger in
§4.4); the interactive cost of the 500-row model reset.

## 10. Remaining risks

1. **Memory and startup cost**: three sources retain separate parsed sync-database caches (≈126 MiB in the historical
   measurement) plus the Explore index. They load when the application starts. Measure RSS on the shipped build before
   changing cache ownership; sharing a cache or releasing Explore's handle after conversion are possible follow-ups.
2. **Search performance after Unicode folding**: the timing table in §4.4 predates Unicode case folding. Measure index
   construction and broad-query latency on the shipped build and a slower target; move search off the GUI thread if it
   exceeds the ~8 ms trigger.
3. **500-row interaction cost**: delegate creation and layout during a reset have not been measured. The theme checklist
   covers visual behavior, while a slow-machine performance check remains useful.
4. **Cache invalidation**: the ALPM cache notices file-list and mtime changes. A sync database replaced while preserving
   both path and mtime can remain cached until a later change or application restart.
